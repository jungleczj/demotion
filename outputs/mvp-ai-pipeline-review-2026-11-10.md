# MVP 的 AI 使用复盘与改造顺序

日期：2026-11-10。对象：本地 GoMotion 风格 MVP；重点项目「海洋，比我们想象的更辽阔」。

## 结论

当前版本接通了素材装配流程，但最关键的视觉理解与剪辑决策仍然缺失。文字模型根据素材目录作选择，不能等同于看过视频。色彩、比例、作者和同片连续取段属于辅助算法，不能承担理解内容、找到动作和规划叙事的工作。

下一轮优先投入“视觉 AI 看候选片段 → 找可用时间区间 → 结合旁白规划整片时间轴”。暂停继续扩充主题数量和堆叠固定规则。

本文件是基于当前代码、接口配置和候选目录的架构复盘。当前电脑控制工具返回浏览器访问被关闭，未取得海洋项目的实际时间轴与成片，因此不声称已经观看或完成该成片的视觉审计。Product Design 的 audit 技能要求实际截图作为审查证据，本次无法完成其截图审查部分。

## 1. 现在究竟哪里用了 AI

| 环节 | 当前实现 | 模型实际能看到什么 | 主要缺口 |
|---|---|---|---|
| 可选脚本撰写 | 文字大模型 | 主题文字 | 不知道可获得哪些实际画面 |
| 拆解脚本、生成英文检索词和画面描述 | 文字大模型；失败回退逐句规则 | 完整脚本 | 无候选画面约束，规划可能无法落地 |
| 选择素材来源 | 主题表与固定路由 | 主题和来源是否启用 | 不会根据实际素材覆盖情况灵活调整 |
| 搜索素材 | 素材库搜索 API | 搜索词 | 搜索 API 本身不是我们的视觉审核；标签可能宽泛、重复或错误 |
| 逐镜头候选排序 | 文字大模型；失败回退元数据分数 | 标题、说明、尺寸、作者、总时长 | 没有接收缩略图、视频帧、视频或音频 |
| 整片组合选材 | 最近补充的确定性算法 | 缩略图色彩直方图、比例、目录分数、作者 | 不认识主体、动作、景别、镜头方向和叙事转折 |
| 决定素材起点 | 默认 0 秒；手工设置；同片续接计算 | 数值 | 不知道动作在第几秒发生，或是否在源片内部切镜 |
| 配音 | macOS 本地 TTS | 每一镜头单独的文字 | 没有整篇连续表演和逐词时间戳 |
| 节奏、字幕、转码、合成 | 估算时长、均分字幕、FFmpeg | 数值和所选文件 | 无语义剪辑规划，无合成后的视频复审 |

代码依据：

- `gomotion-mvp/server/planner.mjs` 的 `llmJSON` 发送文本 messages；`rerank` 的 candidates 仅包含文字和数值。
- `gomotion-mvp/server/sequence.mjs` 的 `fingerprint` 提取 RGB 直方图、亮度、饱和度；`transition` 为固定加减分，没有视觉模型调用。
- `gomotion-mvp/server/render.mjs` 逐段运行 `say`，按设定起点读取视频，并执行 FFmpeg 合成。

`aiConnected=true` 只能证明有密钥配置，不能证明某次生成的每一步成功用了 AI。目前规划返回 method、排序返回 rankMethod，但这些结果没有完整保存为项目运行记录，无法仅凭项目标题还原这一次是否回退。应在后续加入明确的逐阶段记录。

## 2. 海洋项目暴露的问题

示例脚本依次讲海岸、浅海珊瑚、鲸鱼、深海、夕阳海面，天然包含环境变化。合理的镜头连接需要理解这些变化，而非强制所有画面保持相同颜色。

当前候选缓存中存在：

- Pixabay `320960`：鲸鱼相关标签，同时明确包含 `generated ai`。
- Pixabay `4788`：地球相关标签，同时包含 `animation`、`rendering`、`3d model`。
- 另有多段竖屏海岸素材，以及与海洋明显不一致的城堡、山村、猫头鹰目录条目。

这些是候选污染的证据，**不是它们被最终选入海洋成片的证据**。缓存没有保存镜头到最终选择的完整对应关系。

失败可能分为三个层次：

1. 内容不对：旁白说深海，画面只是普通海面；旁白说鲸鱼，画面只有海浪。
2. 片段不对：素材中有鲸鱼，但默认截取的前几秒没有鲸鱼，或者动作进行到一半被切断。
3. 衔接不对：每段单看都相关，但摄影风格、运动方向、光线和旁白停顿组合起来不自然。

色彩比较只能辅助第三层的一小部分。缩略图通常也不能证明动作、最佳取段时间及整个视频的内容。

## 3. 推荐的新流程

### A. 文字 AI 做整篇视觉规划

先定义视觉语言：实拍纪录片或动画、叙事顺序、环境变化、需要精确对应的实体、哪些画面可以作概念表达。将段落拆为视觉节拍，而非机械地一句旁白对应一个文件。

海洋案例可规划为“海岸远景 → 水下过渡 → 珊瑚近景 → 鲸鱼较长镜头 → 深海 → 海面收尾”。这只是待素材检验的方案，不能捏造已有相关片段。

### B. 先取得连续旁白及时间边界

对整篇配音，取得词或短句的时间信息，再决定画面长度。支持时间戳的 TTS 或强制对齐方案可用于此处。避免每句各自配音造成语气和停顿割裂。

### C. API 检索，文字 AI 先缩小候选

保留多来源搜索，但每镜头先筛到少量候选。允许模型提出新的搜索词，设置有限的补搜次数。优先找同作者、同系列、同地点的相关镜头；这些线索提供连续性机会，不能当作连续性保证。

### D. 视觉 AI 真正检查候选

第一轮读取少量低分辨率帧，识别画面主体、环境、景别、光线、构图、明显水印与风格差异。必须允许输出“看不清／不匹配／没有可用素材”。

对进入下一轮的片段，读取有时间信息的连续帧或低分辨率短视频，判断动作与可用时间段。单张封面或三张离散帧不足以可靠判断动作连续性。

要求结构化输出：

```json
{
  "assetId": "retrieved-id-only",
  "observedSubject": "实际看见的主体",
  "environment": "实际看见的环境",
  "shotScale": "wide / medium / close / unknown",
  "cameraMotion": "描述或 unknown",
  "usableIntervals": [{"start": 2.4, "end": 8.1, "reason": "该区间内可见的动作"}],
  "uncertainties": [],
  "reject": false
}
```

时间必须指向真实读取过的画面；服务端再校验来源 ID、时长和区间边界。模型输出的具体身份、地点或物种仍需来源信息交叉核对。

### E. AI 结合完整旁白和视觉证据规划时间轴

输入全部镜头的视觉观察和可用区间，再选择组合、取段和切点。相邻镜头要考虑叙事关系、动作方向、景别和停顿；海面到深海的合理明暗变化应当保留。

一个好画面可以跨两句旁白；一句较长旁白也可以使用两个有关系的镜头。不要求每段都换文件。

### F. 确定性程序执行

FFmpeg 负责裁切、缩放、转码、字幕、音量和时间轴执行。格式检查、时长约束、下载上限、来源记录、取消和清理也由程序保证。让 AI 决定内容相关的剪辑选择，并不意味着所有执行步骤都必须交给 AI。

### G. 对实际低清合成片复审

将合成结果而非只有剪辑 JSON 交给视觉模型检查，再结合人工判断。明显错配、突然倒回、断动作、黑帧、字幕遮挡等应记录位置。限制自动修订次数，保留用户锁定的片段。

视觉模型能帮助审片，不能保证审美、实体识别和时间定位完全正确。

## 4. 不建立全网素材仓库的实现方式

- 只对用户本次脚本检索，不预先处理全库。
- 元数据先筛选，再分析少量候选的缩略图和低清片段。
- 优先使用素材提供方的预览流，临时抽帧、分析后清理。
- 小帧和结构化观察可以短期缓存，设置容量和过期时间。
- 只对最终选定素材下载导出所需文件。
- 给每个任务设置候选数、读取字节、并发、补搜次数、视频分析时长和模型费用上限。

抽帧不等于零下载。远程视频是否支持 Range、索引位置和编码格式都会影响实际读取量；若服务必须读取整个视频才能取得目标帧，应使用受控低清临时文件或更换候选。不能承诺“只读三帧就一定只消耗三帧的流量”。

## 5. 接什么 AI 能力

现有文字 AI 可继续做脚本和检索规划。新增视觉服务应与文字服务独立配置，不能只把文字模型的提示词改成“请看视频”。

- 多图视觉模型：适合候选内容粗筛。OpenAI 官方文档支持一次请求提供多张图片；图片理解不能替代连续视频的运动判断。
- Gemini 的视频理解接口：适合带时间信息的片段观察，官方文档提供采样与片段区间控制。实际选型需用海洋案例比较质量、延迟、费用和账户可用性，不在验证前指定它必然胜出。

目前配置的是素材 API 和文字规划服务，尚未接入上述视觉处理链路。此次没有发起新的付费视觉或视频生成任务。

## 6. 下一轮验证顺序

| 优先级 | 交付 | 验证问题 |
|---|---|---|
| P0 | 保存每阶段实际引擎、模型、输入类型、是否回退、耗时、费用信息 | 到底有没有真正把画面交给 AI？ |
| P0 | 只针对海洋项目，视觉筛选小批候选，记录可用区间 | 选中的内容是否正确，前几秒是否真有目标主体？ |
| P1 | 整篇配音对齐与 AI 时间轴 | 镜头长度、动作切点与停顿是否自然？ |
| P1 | 相邻片段与实际成片的视觉复审，有限补搜 | 整片是否比原版减少错配和跳变？ |
| P2 | 扩展到第二、第三个题材，比较失败类型 | 改进能否迁移到其他内容？ |
| P3 | 更广主题、更多素材来源、高级转场和包装 | 核心内容剪辑通过后再扩张 |

建议先做一段 20–30 秒、3–5 个镜头的海洋片段，固定脚本、旁白和候选集，比较现有目录排序与视觉筛选方案，避免通过改脚本或换候选掩盖方法差异。再单独验证补搜能力。

人工评价应分开记录：内容匹配、风格统一、动作衔接、旁白节奏、需要替换的镜头数。不得只用一个模型分数声称“自然度提升”。本轮未执行这些验证。

## 7. 对 GoMotion 的证据边界

GoMotion 官方条款明确描述使用检索来的 stock/public footage 与图片进行装配，也列出 AI 服务用于脚本分析与镜头/图形规划。这支持“包含素材装配”的判断，但没有公开足够信息证明其具体素材 API、视觉模型、排序模型、时间定位算法，亦不能据此排除其任何场景使用 AI 生成内容。

因此本方案是基于已发现缺口提出的可验证实现路线，不是宣称还原了 GoMotion 的内部系统。
