# 第12项补充：GoMotion 背景、音乐与 Motion graphics 的实现证据

核对日期：2026-11-11。仅研究 gomotionai.com 公开发出的网页和 JavaScript，不登录、不调用其生成任务。本文区分静态实现、开发注释与实际运行记录。

## 主要结论

本次证据比首页截图更强：**公开编辑器包含 Remotion 播放器、按数据选择的动画组件、独立视频/音频/叠加层/字幕轨道，以及预渲染动效缓存分支。** 可以确认用户看到的选项对应独立的编排参数；不能再把它简单理解成“搜索几段实拍后直接串起来”。

这仍没有揭示主要实拍库、后台规划模型或地图数据供应商，也没有证明每个成片都经过相同的渲染分支。

## 1. Background 是独立的背景资源

[创建页](https://gomotionai.com/app)有五种背景：[接口说明](https://gomotionai.com/developers)也接受这五个名称。公开页面的选择状态会映射到固定文件，而不是触发视频搜索。

| 名称 | 创建参数对应的资源名 | 页面预览 |
|---|---|---|
| Blue | background4.mp4 | bg0.jpg / bg0.mp4 |
| Cinematic | background3.mp4 | bg1.jpg / bg1.mp4 |
| Vintage | background5.mp4 | bg2.jpg / bg2.mp4 |
| Light | background2.mp4 | bg3.jpg / bg3.mp4 |
| Grid | background.mp4 | bg4.jpg / bg4.mp4 |

编辑器的合成函数另外读取项目的 background.path/enabled，并把背景放在较底层。**合理解释是图形、照片或标题等元素的统一承载背景**；它不等于整片每个镜头都要更换成这一段背景视频，也没有证据证明它会统一给实拍套某个调色滤镜。具体露出范围取决于叠加层是否全屏及实际镜头安排。

## 2. Motion graphics 是单独的流程开关

创建页明确把图表、地图和动画标题放在这一开关下；提交任务时，开关作为 animations 布尔值进入 options。默认开启，字幕和音乐另有自己的参数。这些是可直接核对的前端行为，不是截图推断。

页面还有一段带日期的开发注释：关闭开关会跳过第三阶段的动画处理及图形渲染；注释称该阶段输入约20万tokens、成本较高。**这是公开代码中开发者的说明，不是本次取得的模型请求日志**；不能据此确定模型、每片都消耗该数量，或把它当成当前生产耗时基准。

它加强了“独立动效规划/渲染阶段”的判断，但不能证明图表只在视频搜索失败时出现。现有证据更支持系统可以按表达需要主动加入动效。

## 3. 已找到真正的图形组件与数据消费路径

[公开编辑器入口](https://gomotionai.com/editor/)实际引用[这个 JavaScript 包](https://gomotionai.com/editor/assets/index-Dz6NhqRH-barxt-20261021-p5guardado.js)。包内不只出现 Remotion 名称，还实际创建播放器并传入项目、画幅、帧率和总帧数；合成函数再读取各轨道内容，按起点与持续帧数安排元素。

可核对的结构包括：

- video、audio、overlay、subtitle 四类轨道；音频支持起点、源内起点、音量与循环。
- 动效项含 animationType、chartData、start、duration、z 等字段。
- 图形选择器按类型把 chartData 转为组件属性。例如环形图消费百分比、标签、颜色、尺寸；折线图消费数据点、轴标签、值前后缀等。
- 动态加载的组件包括环形/折线/柱形/对比图、标题卡、引语卡、证据板、分屏、数字增长、要点面板、图片揭示和排名等。地图表达类型也出现在全屏/相邻场景处理集合中。
- 实际读取的[环形图组件](https://gomotionai.com/editor/assets/DonutChart-CcKBicy2.js)和[证据板组件](https://gomotionai.com/editor/assets/EvidenceBoard-C0xUxxXU.js)，可以进一步核对其参数和逐帧计算；本轮没有执行第三方组件。

因此，“参数化组件 + 时间轴 + 媒体资源”现在有直接的前端实现证据。**可确认编辑器使用 Remotion；服务器最终导出是否始终使用同一引擎，尚不能确认。** 没有找到某个图表库名称不构成证明它没有使用该库。

## 4. 为什么它能够统一风格、减少转场突兀

公开合成代码包含相邻动效边界判断，按帧率容差决定是否抑制入场/退场动画；同时区分有背景的全屏表达和普通叠加。这说明至少在编辑器里，动效过渡考虑了相邻镜头，而不只是每段独立播放自己的开头和结尾。

另一个分支在满足渲染状态、缓存开关和合法 cachePath 时读取透明的预渲染叠加视频；否则走图形组件。由此能确认**存在复用已烘焙动效的实现路径**，但不能确认命中率、服务端缓存策略或收费。

对风格一致的合理解释是：同一组件体系控制字体、色板、背景和动画节奏；不同素材只是其中的输入。它不要求所有画面来自同一段天然连续的视频。本轮没有登录编辑器做替换前后的交互实验。

## 5. 背景乐：目录、试听与制作参数是分开的

创建页从[公开音乐目录](https://gomotionai.com/music/catalog.json)读取曲目，提供六类情绪、具体选曲、试听、音量和上传。代码的优先级为：上传文件优先；其次指定曲目；未指定时取所选类别第一首；目录未加载时提交类别供后台解析。默认状态的音量是0.03，不能把页面另一个兜底值0.05当作所有实际任务的设置。

页面实际试听地址由 /music/、类别和文件名组成。本轮已从这一实际路径取得一首159.02秒、3.62MB的MP3，并完整解码，**没有调用音乐生成或 YouTube Data API 搜索**。[音乐进展](gomotion-background-music-2026-11-11.md)。曲目逐项许可和自动混音仍未完成。

## 6. 对当前 MVP 的结论

建议把后台按表达任务规划为：实拍、来源图片/档案、数据图表、地图/路线、标题/引语等，再统一编排字幕、旁白和音乐。当前来源图标注只是其中一小部分，不能宣称已经复刻整套能力。

- 先把连续旁白和实际时间轴建立好，再安排合适的表达；不要求“一句只能一个完整素材”。第10项仍仅研究，未改变当前拆分代码。
- 不应为补齐画面随意补造统计数据、地理关系或事实。来源照片、图表数据、地图边界和历史时点须另外追溯；图表组件的默认展示值不是事实依据。
- 过渡取决于相邻场景的表达和背景，预先准备/缓存图形可以减少切换成本；不能据此承诺性能提升已测得。
- 前台保持粘贴脚本、选择声音后生成。研究这些选项不等于现在要增加所有高级开关或复杂多轨操作。
