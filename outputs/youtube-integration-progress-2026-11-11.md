# YouTube 检索接入进展

2026-11-11。用户已提供 Data API 凭证并要求接入。凭证未写入源码、报告或环境文件；服务支持在进程内存接收它。

## 已实现

- [检索客户端](gomotion-mvp/server/youtube.mjs)：调用官方 `search.list`，默认筛选 Creative Commons；再以一次 `videos.list` 批量核对信息。过滤无效 ID、不可嵌入、非公开、非已处理、直播及无法确认时长的记录。
- 同关键词 / 筛选 / 凭证的结果在内存缓存 24 小时，最多 100 组。并发相同检索合并；取消一个调用不应取消其他订阅。只存有限元数据，不下载视频或音乐，不建立原片仓库。
- 密钥通过请求头发送，不进 URL；上游错误改写为受控错误，额度耗尽不自动重试。密钥轮换不会共享旧凭证缓存。
- [服务入口](gomotion-mvp/server/index.mjs)：支持 `YOUTUBE_API_KEY` 或既有 `POST /api/config` 的 `youtubeKey`。公开配置仅返回 `youtubeConnected` 布尔值。新增 `POST /api/youtube/search`，请求体支持 `query`、`license`（默认 creativeCommon）、`language`、`maxResults`（最多24）。
- 响应单独放在 `references`，包含来源页、作者频道、时长、目录许可和核对时间，明确 `needsOriginal:true`。**不提供伪造的 downloadUrl / playbackUrl，不写入可用素材注册表。** 现有素材列表仍只显示实际可播放、可下载的文件。
- 保持现有前台布局；本轮没有把来源线索混入“可使用素材”列表，也没有新增复杂创作选项。

## 验证与边界

- [客户端检查](gomotion-mvp/server/youtube.test.mjs)：7 项离线检查通过，覆盖检索与信息合并、许可过滤、缓存隔离、错误脱敏、缺凭证与取消、空结果、并发去重、取消订阅隔离及异常响应。核心5项先运行缺实现的失败检查，再实现并通过；补充2项是既有行为回归。
- 本轮没有发起用户真实 key 的请求，真实连通性、配额与权限尚未验收。运行中的旧服务还未加载本轮后台修改；本地接口操作此前被自动审批额度阻塞，未通过其他方式绕过。
- Data API 本身不返回可供剪辑的原 MP4。自动发现参考不等于自动拿到剪辑素材。取得独立交付的可用原文件后，仍须走现有上传 / 解码 / 方向 / 内容检查，才能入片。
- [官方接口、费用及获取原片的调研](youtube-footage-access-2026-11-11.md)。

## 剩余验收

加载新版服务后，在内存配置用户凭证；以一次实际搜索验证鉴权、响应与缓存命中。确认日志、导出 JSON、任务记录没有密钥。用户可观看来源页，但不能把来源页当作已经取得的原视频用于导出。

## 16:11起：真实连接与主服务加载

此前真实API权限阻塞已解除；隔离3028服务内存配置凭证后，以whale migration ocean作一次search.list与批量videos.list核对，200返回5条公开、可嵌入、CC目录结果，耗时978ms；重复相同查询10ms且cacheHit=true。没有下载视频、没有模型调用。[真实脱敏响应](youtube-live-acceptance-2026-11-11.json)。

确认用户原制作任务终态后切换主3027服务，已加载新接口并恢复内存连接；配置公开响应youtubeConnected=true。此布尔值仅说明已配置，真实鉴权由上面的检索结果证明。Y1后台接入验收通过；前台没有新增YouTube搜索入口，参考结果也不会进入可播放素材列表。Data API不交付原MP4的边界不变。
