- 例如纪录片分类包含 *American Frontiers — Aaron Kenny*、*Keys To Unravel — The Soundlings*。这证明其公开目录对来源的声明；没有证明所有成片都使用这些曲目，也没有证明它从普通 YouTube 视频里提取音乐。

## 能否直接从 GoMotion 取音频

**目录可读，原音频直链尚未验证。** 目录给出的文件名与开发参数 `<mood>/<file>.mp3` 不是已确认的下载 URL。本轮 Web 工具无法读取一个依此推测的 MP3 路径；没有取得 HTTP 状态或可解码文件，不能将该工具错误写成 404，也不能声称音频已拿到。

即使某个 MP3 静态地址可访问，也只说明技术可取得。上线使用前仍应保存对应曲目的实际许可依据；GoMotion 的目录声明不能代替逐曲核对。优先取得 YouTube 官方音频库的同名原文件，不必从混有旁白、音效的成片分离音轨。

## 建议实施方式

1. 从官方音频库按上面的曲名和作者取得原 MP3，保存曲名、作者、获取时间、许可及署名要求。
2. 首批按六类情绪整理约 6–12 首即可。只缓存音乐，不建立视频仓库。例如 12 首、每首 3 分钟、192 kbps 约 **52 MB**，这是容量估算，不是本轮下载测量。
3. 根据已完成的脚本规划选择情绪，用本地规则从该类中挑曲；无需新增模型请求。无合适曲目时可保留纯旁白，不能随意使用未知许可音乐。
4. 本地处理音量、循环接缝、片头片尾淡化；旁白期间自动压低背景音乐。最终审片检查音乐是否遮盖人声、有无突断、循环是否自然，并保留来源记录。

**配乐阶段的目标成本：0 次音乐生成、0 次 YouTube Data API 检索。** 首次获取音频仍有普通下载流量和少量存储；整片制作原有的配音、选材及审片模型调用另计。
